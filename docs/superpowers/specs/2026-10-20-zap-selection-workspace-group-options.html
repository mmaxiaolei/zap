Revision · Workspace Group Card

Zap · Workspace 组卡片选中态 · 修订四方案

关键修复：选中容器必须包住 worktree 头行 + 其下全部子 tab 成一块卡片； 组内再单独高亮当前激活 tab。其它 workspace 在卡片外、无选中态。 色板：Zap 蓝 #1677ff · 可选 Orca 橙 #f5a524。未实现 Rust。

相对上一版被拒原因： 先前 A–D 的圆角/边框只罩在 worktree 单行上，子 tab 落在容器外。 用户要求：「包住的是 workspace 连同其下的所有 tab，同时需要能清晰看到当前选中的是哪个 tab」。
A 蓝组卡片 · 左 pill 激活 tab group card + left inset pill

整组抬升蓝边卡片 + 左侧蓝竖轨；组内激活 tab 用淡蓝底 + 左侧 inset pill。未激活 tab 仍在卡内、低对比可读。

优点组边界清晰；激活与组同色系、易扫；实现是「父容器 + 子行 inset」两层。
缺点蓝轨 + 蓝 pill 略同质；激活强度弱于实心填充。

修订要点（对照被拒版）

  • 结构硬约束：每个方案的 DOM 都是 .ws-group.is-selected 包住 .ws-head + 全部 .tab-row；其它 workspace 用 .ws-plain 留在卡片外。
  • 双层选中：① 组卡片 = 哪个 workspace 聚焦；② .tab-row.is-active = 组内哪个 tab。二者必须同时可见。
  • 激活 tab 变化轴：A 左 pill · B 实心填充 · C 顶条 · D 橙组+蓝填充 —— 在同一「组卡片」骨架上只换组内 tab 强调手法。
  • 推荐讨论：要品牌统一 → A/B；要 Orca 扫描 → C；要「哪里/哪个会话」语义 → D。
  • 非目标：不改 Rust、不推远程、不改树数据模型。
